## Что такое EDA

**EDA** (exploratory data analysis, исследовательский анализ данных) — первое знакомство с новыми данными. Прежде чем отвечать на вопрос заказчика, аналитик выясняет, что вообще лежит в таблице, насколько ей можно верить и какие в ней есть закономерности. Пропустишь этот шаг — и через неделю выяснится, что половина выручки задвоилась из-за дублей, а «падение продаж» — это просто неполный последний месяц.

EDA удобно проходить по чек-листу из шести шагов.

## Шаг 1. Размер и типы

```python
print(orders.shape)          # строки и столбцы
print(orders.dtypes)         # типы: числа, даты, текст
print(orders.head(3))
```

Проверь, совпадает ли число строк с ожиданием и правильно ли распознаны типы. Если дата пришла текстом, а сумма — строкой с пробелами, дальнейшие расчёты будут неверными.

## Шаг 2. Пропуски и дубликаты

```python
print(orders.isna().mean().round(3))        # доля пропусков в каждом столбце
print("дублей строк:", orders.duplicated().sum())
print("дублей номера заказа:", orders["order_id"].duplicated().sum())
```

Для каждого столбца с пропусками реши, что они **значат**. Пустой `promo_code` — это «промокода не было», и это нормально. Пустая `delivery_date` у доставленного заказа — уже ошибка данных. Дубли ключа (`order_id`) — почти всегда проблема: выручка посчитается дважды.

## Шаг 3. Распределения

```python
print(orders["amount"].describe().round(0))
```

`describe()` даёт количество, среднее, стандартное отклонение, минимум, квартили и максимум. На что смотреть:

- **среднее намного больше медианы (50%)** — длинный правый хвост, есть очень крупные значения;
- **минимум 0 или отрицательный** — возвраты, тестовые заказы, ошибки;
- **максимум подозрительно круглый или огромный** — заглушки вроде 999 999.

Распределение лучше один раз увидеть на гистограмме:

```python
import matplotlib.pyplot as plt

delivered = orders[orders["status"] == "delivered"]
plt.hist(delivered["amount"], bins=50)
plt.title("Распределение сумм доставленных заказов")
plt.xlabel("Сумма, ₽")
plt.ylabel("Число заказов")
plt.show()
```

Для категорий — `value_counts()`: какие значения бывают и сколько их. Здесь же всплывают «москва» и «Москва» как разные города.

## Шаг 4. Выбросы

Классическое правило **IQR** (межквартильный размах из темы про разброс): выбросы — значения дальше чем 1,5 × IQR от квартилей.

```python
delivered = orders[orders["status"] == "delivered"]
q1, q3 = delivered["amount"].quantile([0.25, 0.75])
iqr = q3 - q1
upper = q3 + 1.5 * iqr
print("граница:", upper, " выбросов:", (delivered["amount"] > upper).sum())
```

Выброс — не обязательно ошибка. Крупный корпоративный заказ — настоящие деньги. Решение «удалить, оставить или рассмотреть отдельно» зависит от вопроса. Но знать о выбросах нужно всегда: они сильно двигают среднее.

## Шаг 5. Связи между признаками

```python
print(production[["planned_units", "produced_units", "defect_units", "downtime_min"]].corr().round(2))
```

Матрица корреляций быстро показывает, что с чем связано. Для пары числовых признаков нагляднее точечный график (`plt.scatter`). Для «число × категория» — средние по группам (`groupby`). Для «категория × категория» — `pd.crosstab`.

## Шаг 6. Время и сегменты

Почти любые данные стоит посмотреть **во времени** (ряд по дням или месяцам) и **в разрезах** (города, каналы, категории). Так находятся неполные периоды, сбои в сборе данных и сегменты, которые ведут себя иначе.

```python
merged = orders.merge(customers[["customer_id", "acquisition_channel"]], on="customer_id")
by_channel = (merged[merged["status"] == "delivered"]
              .groupby("acquisition_channel")
              .agg(clients=("customer_id", "nunique"), revenue=("amount", "sum")))
by_channel["revenue_per_client"] = (by_channel["revenue"] / by_channel["clients"]).round(0)
print(by_channel.sort_values("revenue_per_client", ascending=False))
```

## Итог EDA — короткие выводы

EDA заканчивается не горой графиков, а несколькими фразами для себя и заказчика:

1. **Качество данных:** «пропуски в `delivery_date` — это отменённые и ещё не доставленные заказы, ошибок нет; дублей нет».
2. **Особенности:** «суммы сильно скошены: медиана 5 500 ₽, среднее 11 800 ₽. Для типичного чека используем медиану».
3. **Первые находки и гипотезы:** «клиенты из рекомендаций приносят больше выручки на человека — стоит проверить».

> 💡 Не утони в EDA. Цель — понять данные настолько, чтобы уверенно ответить на конкретный вопрос, а не изучить всё на свете.

## Шпаргалка

| Шаг | Код |
|---|---|
| размер и типы | `df.shape`, `df.dtypes`, `df.head()` |
| пропуски | `df.isna().mean()` |
| дубли | `df.duplicated().sum()`, `df["id"].duplicated().sum()` |
| распределение | `df["x"].describe()`, `plt.hist(df["x"], bins=50)` |
| категории | `df["c"].value_counts()` |
| выбросы по IQR | `q3 + 1.5 * (q3 - q1)` |
| связи | `df[cols].corr()`, `plt.scatter(x, y)`, `pd.crosstab(a, b)` |
| сегменты | `df.groupby("seg").agg(...)` |
