## Рабочее место аналитика

В приложении код запускается одной кнопкой. На работе вокруг кода есть ещё несколько инструментов, и без них не обходится ни одна команда:

- **Jupyter** — тетрадка, где код, результаты и пояснения лежат вместе;
- **командная строка** — запуск скриптов и установка библиотек;
- **виртуальное окружение** — свой набор библиотек для каждого проекта;
- **Git и GitHub** — история изменений, совместная работа и портфолио.

Хорошая новость: для старта хватит десятка команд.

## Jupyter: ноутбуки

**Jupyter Notebook** (и его современная версия JupyterLab) — главный инструмент аналитика на Python. Ноутбук состоит из **ячеек**:

- **ячейки кода** выполняются по `Shift + Enter`, результат появляется прямо под ними;
- **ячейки Markdown** — текст с заголовками, списками и формулами. В них объясняют, что и зачем делается.

Ноутбук можно запустить на своём компьютере, в VS Code или в облаке: **Google Colab** и **Yandex DataSphere** работают прямо в браузере, ничего ставить не нужно.

> ⚠️ **Главная ловушка Jupyter — порядок выполнения.** Ячейки можно запускать в любом порядке, и переменные из удалённой ячейки продолжают жить в памяти. Ноутбук «работает» у тебя, но падает у коллеги. Перед тем как отправить ноутбук, всегда делай **Kernel → Restart & Run All**: перезапуск и выполнение сверху вниз. Если всё отработало — ноутбук честный.

Полезные мелочи:

| Действие | Как |
|---|---|
| выполнить ячейку | `Shift + Enter` |
| новая ячейка ниже / выше | `B` / `A` (в режиме команд, после `Esc`) |
| превратить в Markdown / в код | `M` / `Y` |
| время выполнения ячейки | `%%time` первой строкой |
| подсказка по функции | `Shift + Tab` или `?имя` |

## Командная строка

Командная строка (терминал) — текстовый способ управлять компьютером. Аналитику она нужна, чтобы ставить библиотеки, запускать скрипты и работать с Git.

```bash
pwd                      # где я нахожусь (в Windows: cd без аргументов)
ls                       # что в папке (в Windows: dir)
cd projects/sales        # перейти в папку
cd ..                    # подняться на уровень вверх
mkdir data               # создать папку
python report.py         # запустить скрипт
```

**Путь** — адрес файла. Абсолютный начинается от корня диска (`C:\Users\anna\sales\data.csv`), относительный — от текущей папки (`data/data.csv`). Большинство ошибок «файл не найден» — из-за того, что скрипт запущен не из той папки.

## Библиотеки и виртуальные окружения

Библиотеки ставят менеджером пакетов `pip`:

```bash
pip install pandas matplotlib
pip install -r requirements.txt     # всё по списку из файла
pip freeze > requirements.txt       # сохранить список установленного
```

Разным проектам нужны разные версии библиотек. Чтобы они не мешали друг другу, для каждого проекта создают **виртуальное окружение** — отдельную папку со своим Python и своими пакетами:

```bash
python -m venv .venv               # создать окружение в папке .venv
.venv\Scripts\activate             # включить (Windows)
source .venv/bin/activate          # включить (macOS, Linux)
pip install -r requirements.txt    # поставить библиотеки проекта
```

Файл `requirements.txt` с версиями библиотек кладут в проект. Тогда коллега за две команды получит такое же окружение, и код у него заработает так же. Популярная альтернатива — **conda** (дистрибутив Anaconda), особенно на Windows.

## Git: машина времени для кода

**Git** запоминает историю изменений проекта. Каждое сохранённое состояние — **коммит** с описанием «что поменялось». К любому коммиту можно вернуться, посмотреть, кто и зачем менял строку, и работать вместе, не затирая чужие правки.

Базовый цикл:

```bash
git init                         # начать следить за папкой (один раз)
git status                       # что изменилось
git add analysis.ipynb           # отметить файл для коммита
git commit -m "Добавил когорты"  # сохранить состояние с описанием
git log --oneline                # история коммитов
```

Совместная работа идёт через удалённый репозиторий — например, на **GitHub** или **GitLab**:

```bash
git clone https://github.com/team/sales.git   # скачать проект
git pull                                      # забрать чужие изменения
git push                                      # отправить свои
git switch -c new-report                      # новая ветка для задачи
```

**Ветка** — параллельная линия изменений. Новую задачу делают в отдельной ветке. Когда она готова, её вливают в основную через **pull request**: коллеги смотрят изменения и оставляют комментарии.

## Что не должно попасть в Git

Файл `.gitignore` перечисляет, что Git должен игнорировать:

```text
.venv/
data/raw/
*.csv
.env
.ipynb_checkpoints/
```

- **Секреты** — пароли, токены, ключи API. Если ключ попал в коммит, его нужно отозвать: удаление следующим коммитом не помогает, история хранит всё.
- **Большие данные** — Git для кода, а не для гигабайтных выгрузок.
- **Личные данные клиентов** — их нельзя публиковать вообще никогда.
- **Мусор** — окружения, кэши, автосохранения ноутбуков.

## GitHub как портфолио

Для начинающего аналитика GitHub — витрина. Работодатель смотрит репозитории с проектами. Хороший проект:

- имеет **README**: какая задача, какие данные, главные выводы, как запустить;
- содержит ноутбук, который выполняется сверху вниз без ошибок;
- имеет понятную структуру папок;
- не содержит секретов и чужих персональных данных.

```text
sales-analysis/
├── README.md
├── requirements.txt
├── data/            ← или ссылка, откуда скачать данные
├── notebooks/
│   └── analysis.ipynb
└── src/
    └── helpers.py
```

## Шпаргалка

| Задача | Команда |
|---|---|
| честная проверка ноутбука | Kernel → Restart & Run All |
| перейти в папку | `cd путь` |
| поставить библиотеку | `pip install имя` |
| создать окружение | `python -m venv .venv` |
| сохранить зависимости | `pip freeze > requirements.txt` |
| что изменилось | `git status`, `git diff` |
| сохранить изменения | `git add файл`, `git commit -m "описание"` |
| обменяться с GitHub | `git pull`, `git push` |
| новая ветка | `git switch -c имя` |
| не хранить в Git | `.gitignore`: `.env`, `.venv/`, данные |
