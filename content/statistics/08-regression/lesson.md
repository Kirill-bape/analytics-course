## От корреляции к формуле

Корреляция говорит, что простои и выпуск связаны. Но руководителю цеха нужно больше: «Если простой вырастет на 10 минут, сколько изделий мы потеряем?» На такой вопрос отвечает **регрессия**. Она подбирает формулу, которая по одной величине предсказывает другую.

**Линейная регрессия** ищет прямую:

```text
y = a + b × x
```

- `y` — что предсказываем (выпуск за смену);
- `x` — от чего зависит (простой в минутах);
- `b` — **наклон**: на сколько меняется `y`, когда `x` растёт на единицу;
- `a` — **свободный член**: значение `y` при `x = 0`.

Прямую выбирают так, чтобы сумма квадратов отклонений точек от неё была минимальной. Это **метод наименьших квадратов**.

## Регрессия прямо в SQL

В DuckDB, PostgreSQL и многих других базах есть готовые функции:

```sql
SELECT ROUND(regr_slope(produced_units, downtime_min), 2)     AS slope,
       ROUND(regr_intercept(produced_units, downtime_min), 1) AS intercept,
       ROUND(regr_r2(produced_units, downtime_min), 3)        AS r2
FROM production
WHERE line_id = 1;
```

Обрати внимание на порядок аргументов: **сначала `y`, потом `x`**.

Как прочитать результат. Наклон около −0,8 значит: каждая лишняя минута простоя в среднем стоит почти одно изделие, а час простоя — около 50 изделий. Свободный член — выпуск смены без простоев. Так абстрактная корреляция превращается в деньги: умножь потерянные изделия на маржу одного изделия.

## R²: насколько хорошо прямая описывает данные

**R²** (коэффициент детерминации) — доля разброса `y`, которую объясняет модель. Меняется от 0 до 1.

| R² | Что значит |
|---|---|
| 0,9 | точки почти на прямой, `x` объясняет 90% колебаний `y` |
| 0,5 | половину колебаний объясняет `x`, половина — другие причины |
| 0,05 | прямая почти бесполезна |

Для простой регрессии R² равен квадрату корреляции: при r = −0,8 получаем R² = 0,64.

> 💡 Низкий R² не всегда плох. Выручка зависит от сотни причин, и модель с R² = 0,3 может приносить пользу. Но прогноз по ней будет с большой погрешностью.

## Прогноз и остатки

Подставь `x` в формулу — получишь прогноз. **Остаток** — разница между фактом и прогнозом:

```text
остаток = факт − прогноз
```

Остатки — полезный инструмент поиска аномалий. Смена с большим отрицательным остатком выпустила намного меньше, чем «положено» при её простое. Значит, дело не в простое, а в чём-то другом. Это повод разобраться.

```sql
WITH model AS (
    SELECT regr_slope(produced_units, downtime_min)     AS b,
           regr_intercept(produced_units, downtime_min) AS a
    FROM production
    WHERE line_id = 1
)
SELECT p.prod_date, p.shift, p.downtime_min, p.produced_units,
       ROUND(m.a + m.b * p.downtime_min) AS predicted,
       ROUND(p.produced_units - (m.a + m.b * p.downtime_min)) AS residual
FROM production p
CROSS JOIN model m
WHERE p.line_id = 1
ORDER BY residual
LIMIT 5;
```

## Регрессия в Python

Для одной переменной удобна функция `scipy.stats.linregress`. Она сразу даёт и p-value для наклона: значимо ли он отличается от нуля.

```python
from scipy import stats

line1 = production[production["line_id"] == 1].dropna(subset=["downtime_min"])
res = stats.linregress(line1["downtime_min"], line1["produced_units"])
print("наклон:", round(res.slope, 2))
print("свободный член:", round(res.intercept, 1))
print("R²:", round(res.rvalue ** 2, 3))
print("p-value наклона:", res.pvalue)
```

Здесь порядок обычный, математический: **сначала `x`, потом `y`**.

> ⚠️ В столбце `downtime_min` есть пропуски: в некоторых сменах простой не записали. SQL-функции `regr_*` сами пропускают строки с `NULL`, а в Python один пропуск превращает весь результат в `nan`. Поэтому перед расчётом убираем такие строки: `.dropna(subset=["downtime_min"])`.

## Несколько факторов: множественная регрессия

Выпуск зависит не только от простоя, но и от опыта оператора. **Множественная регрессия** учитывает несколько `x` сразу:

```text
выпуск = a + b₁ × простой + b₂ × стаж
```

Коэффициент при каждом факторе читается «**при прочих равных**»: `b₂` — на сколько меняется выпуск с каждым годом стажа, если простой тот же. Это главное преимущество перед простыми корреляциями: модель отделяет влияние одного фактора от другого.

```python
import numpy as np

df = production.merge(operators[["operator_id", "experience_years"]], on="operator_id")
df = df[df["line_id"] == 1].dropna(subset=["downtime_min"])

X = np.column_stack([np.ones(len(df)), df["downtime_min"], df["experience_years"]])
coef, *_ = np.linalg.lstsq(X, df["produced_units"], rcond=None)
print("a, b_простой, b_стаж:", coef.round(2))
```

Столбец единиц в `X` нужен для свободного члена `a`. Категориальные признаки (линия, смена) переводят в столбцы из нулей и единиц — **дамми-переменные** (`pd.get_dummies`).

В работе для регрессии обычно используют библиотеки `statsmodels` (подробная таблица с p-value для каждого коэффициента) и `scikit-learn` (для прогнозов, его разберём в модуле машинного обучения).

## Где регрессия обманывает

1. **Экстраполяция.** Модель знает только тот диапазон `x`, на котором её обучили. Если простои были от 0 до 90 минут, прогноз для 400 минут может уйти в минус.
2. **Причинность.** Регрессия, как и корреляция, находит связь, а не причину. Продажи мороженого «предсказывают» число утоплений, но запрет мороженого никого не спасёт: обе величины растут из-за жары.
3. **Выбросы.** Одна аномальная смена может заметно повернуть прямую. Посмотри на график рассеяния до того, как доверять коэффициентам.
4. **Нелинейность.** Если зависимость изогнута (например, насыщается), прямая будет систематически ошибаться. Это видно по остаткам: они идут «волной», а не хаотично.
5. **Связанные факторы.** Если два `x` сильно коррелируют друг с другом (стаж и возраст), их коэффициенты становятся неустойчивыми. Это называют мультиколлинеарностью.

## А если y — «да или нет»?

Для бинарного результата (купит / не купит, уйдёт / останется) прямая не годится: она может предсказать вероятность 130%. Для этого есть **логистическая регрессия**. Её разберём в модуле машинного обучения.

## Шпаргалка

| Задача | Как |
|---|---|
| наклон в SQL | `regr_slope(y, x)` |
| свободный член | `regr_intercept(y, x)` |
| R² | `regr_r2(y, x)` |
| прогноз | `a + b * x` |
| остаток | `факт − прогноз` |
| регрессия в Python | `stats.linregress(x, y)` → `.slope`, `.intercept`, `.rvalue ** 2`, `.pvalue` |
| несколько факторов | `np.linalg.lstsq(X, y)` со столбцом единиц в `X` |
