## Зачем аналитику вероятности

Каждый день аналитик отвечает на вопросы «насколько это вероятно»:

- какая доля заказов закончится отменой;
- с какой вероятностью клиент, открывший письмо, купит;
- случайно ли конверсия выросла с 4 до 5% или это эффект;
- сколько в среднем мы потратим на промокоды.

Теория вероятностей — фундамент всех статистических тестов, A/B-тестов и моделей машинного обучения. Для работы хватит нескольких правил. Разберём их на данных магазина.

## Вероятность как доля

**Вероятность** события — число от 0 до 1. Ноль значит «никогда», единица — «всегда». На данных вероятность оценивают как **долю** случаев, когда событие произошло:

```text
P(событие) = число случаев с событием / число всех случаев
```

```sql
-- Вероятность, что случайный заказ будет отменён
SELECT ROUND(AVG(CASE WHEN status = 'cancelled' THEN 1.0 ELSE 0 END), 4) AS p_cancel
FROM orders;
```

Приём `AVG(CASE WHEN … THEN 1.0 ELSE 0 END)` пригодится постоянно: среднее из единиц и нулей — это и есть доля единиц.

Вероятность того, что событие **не** произойдёт: `P(не A) = 1 − P(A)`. Если 6% заказов отменяют, то 94% не отменяют.

## «Или» и «и»

**Сложение — для «или».** Если события не могут случиться одновременно (заказ не бывает и отменён, и возвращён), их вероятности складываются:

```text
P(отменён или возвращён) = P(отменён) + P(возвращён)
```

Если могут случиться вместе, общую часть нужно вычесть, иначе она посчитается дважды: `P(A или B) = P(A) + P(B) − P(A и B)`.

**Умножение — для «и».** Если события **независимы**, то есть одно никак не влияет на другое, вероятность того, что случатся оба, равна произведению:

```text
P(A и B) = P(A) × P(B)
```

Пример: письмо открывают с вероятностью 0,3. Из открывших по ссылке переходят 10%. Вероятность, что получатель письма перейдёт по ссылке: 0,3 × 0,1 = 0,03. Так считается любая **воронка**: конверсии этапов перемножаются.

> ⚠️ Независимость — сильное допущение. Два заказа одного клиента не независимы: если он вернул первый, вероятность возврата второго выше средней.

## Условная вероятность

**Условная вероятность** P(A | B) читается «вероятность A **при условии** B». Её считают только среди случаев, где B уже произошло:

```text
P(A | B) = P(A и B) / P(B)
```

На данных это просто доля внутри группы. Вероятность отмены **при условии**, что заказ оплачивают наличными:

```sql
SELECT payment_method,
       COUNT(*) AS orders,
       ROUND(AVG(CASE WHEN status = 'cancelled' THEN 1.0 ELSE 0 END), 4) AS p_cancel
FROM orders
GROUP BY payment_method
ORDER BY p_cancel DESC;
```

Если P(отмена | наличные) заметно больше, чем P(отмена) в целом, события зависимы: способ оплаты связан с отменами. Это повод копать дальше, но ещё не доказательство причины.

## Формула Байеса: ловушка редких событий

Система антифрода ловит 95% мошеннических заказов, а ошибочно помечает 5% честных. Мошенников всего 1%. Система подняла тревогу — какова вероятность, что заказ действительно мошеннический?

Интуиция говорит «95%». Посчитаем на 10 000 заказах:

| | Мошенники (100) | Честные (9 900) |
|---|---|---|
| система подняла тревогу | 95 | 495 |
| система промолчала | 5 | 9 405 |

Тревог всего 95 + 495 = 590, и только 95 из них настоящие: 95 / 590 ≈ **16%**. Честных заказов так много, что даже 5% ложных тревог перевешивают. Это и есть **формула Байеса**:

```text
P(мошенник | тревога) = P(тревога | мошенник) × P(мошенник) / P(тревога)
```

Вывод для практики: когда ищешь редкое событие, всегда смотри, какая доля срабатываний **верная**. В машинном обучении это называется точностью (precision).

## Ожидаемое значение

**Ожидаемое значение** (матожидание) — среднее, которое получится на большом числе повторений. Каждый исход умножают на его вероятность и складывают:

```text
E = исход₁ × P₁ + исход₂ × P₂ + …
```

Пример: промокод на 500 ₽ используют 30% получивших. Ожидаемая стоимость рассылки на одного клиента: 500 × 0,3 + 0 × 0,7 = **150 ₽**. На 10 000 клиентов — 1,5 млн ₽. Так оценивают бюджет акции до запуска.

## Биномиальное распределение

Повторяем одинаковый опыт n раз, и в каждом успех случается с вероятностью p. Например, 50 посетителей, каждый покупает с вероятностью 4%. Сколько будет покупок? Ответ — не одно число, а **распределение**: 0, 1, 2… покупок с разными вероятностями. Оно называется **биномиальным**.

В Python его считает `scipy.stats.binom`:

```python
from scipy import stats

n, p = 50, 0.04
print("В среднем покупок:", n * p)
print("P(ровно 2):", round(stats.binom.pmf(2, n, p), 4))
print("P(ни одной):", round(stats.binom.pmf(0, n, p), 4))
print("P(хотя бы одна):", round(1 - stats.binom.pmf(0, n, p), 4))
```

- `pmf(k, n, p)` — вероятность **ровно** k успехов;
- `cdf(k, n, p)` — вероятность **не больше** k успехов.

Даже при средних «2 покупки» с вероятностью около 13% не будет ни одной. Поэтому день без продаж на маленьком трафике — ещё не повод бить тревогу.

## Ошибка игрока

Подряд отменили пять заказов. Значит ли это, что следующий «точно не отменят», потому что отмены «уже были»? Нет. Если заказы независимы, у следующего та же вероятность отмены, что и у любого другого. Случайность не «помнит» прошлое и не выравнивается специально. Это заблуждение называют **ошибкой игрока**.

## Шпаргалка

| Что посчитать | Как |
|---|---|
| вероятность по данным | `AVG(CASE WHEN условие THEN 1.0 ELSE 0 END)` |
| противоположное событие | `1 − P(A)` |
| A или B (не пересекаются) | `P(A) + P(B)` |
| A и B (независимы) | `P(A) × P(B)` |
| условная вероятность | доля внутри группы: `GROUP BY` + доля |
| формула Байеса | `P(A|B) = P(B|A) × P(A) / P(B)` |
| ожидаемое значение | сумма «исход × вероятность» |
| ровно k успехов из n | `stats.binom.pmf(k, n, p)` |
| не больше k успехов | `stats.binom.cdf(k, n, p)` |
