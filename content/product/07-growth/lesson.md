## Откуда берётся рост

Рост продукта — не одна гениальная идея, а система: понять, где узкое место, придумать гипотезы, быстро проверить, масштабировать то, что сработало. Аналитик в этой системе отвечает за две вещи: **где искать** (данные показывают узкие места) и **как проверить** (эксперименты и честная оценка эффекта).

## Пиратские метрики: AARRR

Популярная схема жизненного цикла пользователя — **AARRR** (её называют «пиратскими метриками» за звучание):

| Этап | Вопрос | Пример метрики для магазина |
|---|---|---|
| **A**cquisition — привлечение | откуда приходят люди? | посетители по каналам, стоимость визита |
| **A**ctivation — активация | получил ли человек ценность в первый раз? | доля посетителей, сделавших первый заказ |
| **R**etention — удержание | возвращается ли? | доля сделавших второй заказ за 60 дней |
| **R**evenue — монетизация | сколько платит? | ARPU, маржа, LTV |
| **R**eferral — рекомендации | приводит ли других? | доля новых клиентов по приглашениям |

Ищи этап с самой большой потерей или самым большим потенциалом — туда и направляй гипотезы. Привлекать новых клиентов в продукт с плохим удержанием — как наливать воду в дырявое ведро.

## Активация и «ага-момент»

**Ага-момент** — действие, после которого пользователь понимает ценность продукта и с большей вероятностью остаётся. Классические примеры: в соцсети — добавить 7 друзей за 10 дней, в облачном хранилище — положить файл на одном устройстве и открыть на другом.

Аналитик ищет ага-момент так: сравнивает удержание пользователей, которые **сделали** и **не сделали** определённое действие в начале жизни. Например, связано ли то, что лежало в первом заказе, с тем, вернётся ли клиент:

```sql
WITH first_orders AS (
    SELECT customer_id, order_id
    FROM (
        SELECT customer_id, order_id,
               ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY order_date, order_id) AS rn
        FROM orders
        WHERE status = 'delivered'
    ) t
    WHERE rn = 1
),
first_size AS (
    SELECT f.customer_id, SUM(oi.quantity) AS items
    FROM first_orders f
    JOIN order_items oi ON oi.order_id = f.order_id
    GROUP BY f.customer_id
),
repeat AS (
    SELECT customer_id, COUNT(*) >= 2 AS returned
    FROM orders
    WHERE status = 'delivered'
    GROUP BY customer_id
)
SELECT CASE WHEN fs.items >= 2 THEN '2+ товара' ELSE '1 товар' END AS first_basket,
       COUNT(*) AS clients,
       ROUND(100.0 * AVG(CASE WHEN r.returned THEN 1 ELSE 0 END), 1) AS returned_pct
FROM first_size fs
JOIN repeat r ON r.customer_id = fs.customer_id
GROUP BY first_basket
ORDER BY first_basket;
```

> ⚠️ Найденная связь — гипотеза, а не причина. Возможно, большую корзину собирают люди, которые изначально пришли с серьёзным намерением. Проверка — эксперимент: например, подсказывать сопутствующие товары в первом заказе и смотреть, вырастет ли удержание.

## Гипотезы роста

Рабочий цикл роста:

1. **Анализ**: где узкое место по AARRR и дереву метрик?
2. **Идеи**: много вариантов, от команды, пользователей, конкурентов.
3. **Гипотезы**: каждую идею — в формулу «если… для… то… потому что…».
4. **Приоритизация**: ICE или RICE.
5. **Эксперимент**: быстро и дёшево, чаще всего A/B-тест.
6. **Решение и обучение**: раскатить, доработать или отказаться; записать вывод.

**ICE** — упрощённая версия RICE без охвата:

```text
ICE = Impact × Confidence × Ease   (каждый от 1 до 10)
```

Скорость важнее идеальности: команда, которая проводит 50 тестов в квартал, растёт быстрее команды с 5 тщательно выверенными тестами.

## Петли роста

**Петля роста** (growth loop) — механизм, где результат одного цикла становится входом следующего, и рост ускоряет сам себя:

- **реферальная**: клиент приглашает друга → друг получает бонус и становится клиентом → тоже приглашает;
- **контентная**: пользователи пишут отзывы → отзывы приводят новых посетителей из поиска → новые пишут отзывы;
- **платная**: выручка с клиентов → бюджет на рекламу → новые клиенты → выручка.

Платная петля работает, только если **LTV > CAC**: иначе каждый виток уменьшает деньги, а не умножает их.

## Шпаргалка

| Понятие | Суть |
|---|---|
| AARRR | привлечение → активация → удержание → монетизация → рекомендации |
| ага-момент | раннее действие, связанное с высоким удержанием |
| поиск ага-момента | удержание сделавших vs не сделавших действие → гипотеза → тест |
| ICE | Impact × Confidence × Ease |
| цикл роста | анализ → идеи → гипотезы → приоритеты → тест → решение |
| петля роста | результат цикла становится входом следующего |
