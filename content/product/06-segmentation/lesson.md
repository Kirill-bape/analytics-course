## Зачем делить клиентов на сегменты

«Средний клиент» не существует. Один заказывает раз в год дорогую технику, другой каждую неделю — книги, третий купил один раз по промокоду и пропал. Одно сообщение для всех работает плохо. **Сегментация** — деление клиентов (или товаров) на группы, внутри которых поведение похоже, а между которыми — различается. Цель — **разные действия для разных групп**.

Хороший сегмент:

- **измерим**: понятно, кто в него входит;
- **достаточно большой**, чтобы ради него что-то делать;
- **отличается** от других по поведению или ценности;
- **действенный**: для него есть понятное действие.

## Способы сегментации

| Способ | Признаки | Пример |
|---|---|---|
| по характеристикам | город, возраст, канал привлечения, устройство | «клиенты из рекламы в соцсетях» |
| по поведению | частота, давность, сумма, категории покупок | «покупает только со скидкой» |
| по ценности | выручка, прибыль, LTV | «топ-10% по прибыли» |
| по жизненному циклу | новичок, активный, засыпающий, ушедший | «не покупал 60–90 дней» |
| кластеризация | много признаков сразу, алгоритм сам находит группы | модуль машинного обучения |

## RFM с баллами

В итоговом проекте мы посчитали R, F и M для каждого клиента. Чтобы превратить их в сегменты, каждому показателю присваивают **балл** от 1 до 5 по квантилям: 5 — лучшие 20% клиентов, 1 — худшие 20%. В SQL это делает функция `NTILE`:

```sql
WITH rfm AS (
    SELECT customer_id,
           DATE '2026-06-30' - MAX(order_date) AS recency_days,
           COUNT(*)                            AS frequency,
           SUM(amount)                         AS monetary
    FROM orders
    WHERE status = 'delivered'
    GROUP BY customer_id
)
SELECT customer_id, recency_days, frequency, monetary,
       NTILE(5) OVER (ORDER BY recency_days DESC) AS r,   -- чем недавнее, тем выше балл
       NTILE(5) OVER (ORDER BY frequency)          AS f,
       NTILE(5) OVER (ORDER BY monetary)           AS m
FROM rfm
ORDER BY monetary DESC
LIMIT 10;
```

Обрати внимание на направление: для давности **меньше — лучше**, поэтому сортировка обратная.

Дальше из баллов собирают понятные сегменты, например:

| Сегмент | Условие | Действие |
|---|---|---|
| лучшие | R ≥ 4 и F ≥ 4 | программа лояльности, ранний доступ к новинкам |
| засыпающие ценные | R ≤ 2 и F ≥ 4 | персональное предложение «возвращайтесь» |
| новички | F = 1 и R ≥ 4 | приветственная серия, подсказка второй покупки |
| потерянные | R = 1 и F ≤ 2 | дешёвые каналы или не тратить бюджет |

> ⚠️ У частоты много одинаковых значений: половина клиентов могла сделать ровно один заказ. `NTILE` раскидает одинаковых клиентов по разным баллам случайно. Для частоты часто удобнее простые пороги: 1 заказ, 2–3, 4 и больше.

## ABC-анализ: какие товары важнее

**ABC-анализ** делит товары (или клиентов) по вкладу в выручку:

- **A** — товары, дающие первые 80% выручки (обычно 15–25% ассортимента);
- **B** — следующие 15%;
- **C** — последние 5%, обычно больше половины ассортимента.

Это следствие **принципа Парето**: малая часть объектов даёт большую часть результата. Товары группы A нельзя допускать в дефицит; по группе C стоит подумать, нужны ли они вообще.

```sql
WITH p AS (
    SELECT oi.product_id, SUM(oi.quantity * oi.price) AS revenue
    FROM order_items oi
    JOIN orders o ON o.order_id = oi.order_id
    WHERE o.status = 'delivered'
    GROUP BY oi.product_id
),
c AS (
    SELECT product_id, revenue,
           SUM(revenue) OVER (ORDER BY revenue DESC) / SUM(revenue) OVER () AS cum_share
    FROM p
)
SELECT CASE WHEN cum_share <= 0.8 THEN 'A' WHEN cum_share <= 0.95 THEN 'B' ELSE 'C' END AS abc,
       COUNT(*) AS products,
       ROUND(100.0 * SUM(revenue) / (SELECT SUM(revenue) FROM p), 1) AS revenue_pct
FROM c
GROUP BY abc
ORDER BY abc;
```

Часто ABC дополняют **XYZ** — делением по стабильности спроса (по коэффициенту вариации продаж по неделям). Товар «AX» — важный и предсказуемый, «CZ» — неважный и непредсказуемый.

## Как проверить, что сегментация работает

1. Посчитай для каждого сегмента **размер** и **ценность** (доля клиентов, доля выручки).
2. Убедись, что сегменты **отличаются** по ключевым метрикам: удержание, средний чек, реакция на акции.
3. Для каждого сегмента придумай **действие** и проверь его эффект A/B-тестом внутри сегмента.
4. Пересчитывай сегменты регулярно: клиенты переходят из «новичков» в «лучшие» и из «лучших» в «засыпающие».

## Шпаргалка

| Задача | Как |
|---|---|
| баллы 1–5 по квантилям | `NTILE(5) OVER (ORDER BY x)` |
| давность: меньше — лучше | `NTILE(5) OVER (ORDER BY recency DESC)` |
| накопленная доля | `SUM(x) OVER (ORDER BY x DESC) / SUM(x) OVER ()` |
| ABC | A ≤ 80%, B ≤ 95%, C — остальное |
| Парето | доля выручки от топ-20% клиентов или товаров |
| проверка сегментов | размер, ценность, различия, действие, A/B-тест |
