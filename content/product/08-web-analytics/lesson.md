## Данные о поведении на сайте и в приложении

Таблица заказов показывает итог. А чтобы понять, **как** люди к нему пришли и где застряли, нужны данные о поведении: просмотры страниц, клики, поиск, добавления в корзину. Их собирают системы веб- и мобильной аналитики:

| Система | Для чего |
|---|---|
| **Яндекс Метрика** | сайты: трафик, источники, цели, вебвизор (запись действий) |
| **Google Analytics 4** | сайты и приложения, модель на событиях |
| **AppMetrica**, **Firebase** | мобильные приложения: события, установки, сбои |
| **собственный трекинг** | события пишутся прямо в хранилище (например, ClickHouse) |

## Событие — единица данных

Современная аналитика строится на **событиях**: каждое действие пользователя — строка с полями «кто, что, когда, где»:

```text
user_id | event_time          | event          | page / параметры
1042    | 2026-06-10 12:01:05 | page_view      | /catalog/headphones
1042    | 2026-06-10 12:02:40 | add_to_cart    | product_id=331
1042    | 2026-06-10 12:05:12 | purchase       | order_id=110215, amount=4990
```

До того как собирать данные, команда пишет **план трекинга**: какие события, с какими параметрами, в какой момент отправляются. Без него через полгода окажется, что «добавление в корзину» на сайте и в приложении записывается по-разному и сравнивать нельзя.

## Сессии

**Сессия** — непрерывный период активности пользователя. Обычное правило: если между событиями прошло больше **30 минут**, начинается новая сессия. На событиях это считается так: сортируем действия пользователя по времени, смотрим разрыв с предыдущим и ставим метку начала новой сессии:

```python
events = pd.DataFrame({
    "user_id": [1, 1, 1, 1, 2, 2],
    "event_time": pd.to_datetime(["2026-06-10 10:00", "2026-06-10 10:10", "2026-06-10 11:30",
                                  "2026-06-10 11:35", "2026-06-10 09:00", "2026-06-10 09:50"]),
})
events = events.sort_values(["user_id", "event_time"])
gap = events.groupby("user_id")["event_time"].diff()
events["new_session"] = gap.isna() | (gap > pd.Timedelta(minutes=30))
events["session_id"] = events.groupby("user_id")["new_session"].cumsum()
print(events)
print("сессий:", events["new_session"].sum())
```

Базовые метрики сессий: число сессий, длительность, глубина (страниц за сессию), **отказы** (bounce rate) — доля сессий из одной страницы или короче 15 секунд (в разных системах по-разному).

## Источники трафика и UTM-метки

Чтобы знать, откуда пришёл пользователь, к ссылкам в рекламе добавляют **UTM-метки**:

```text
https://shop.example/catalog?utm_source=yandex&utm_medium=cpc&utm_campaign=summer_sale
```

| Метка | Что означает | Пример |
|---|---|---|
| `utm_source` | источник | yandex, vk, email |
| `utm_medium` | тип трафика | cpc (платный клик), email, social |
| `utm_campaign` | кампания | summer_sale |
| `utm_content`, `utm_term` | объявление, ключевая фраза | banner_red |

Без единых правил разметки отчёт по каналам превращается в кашу из «Yandex», «yandex» и «ya». Договоритесь о словаре меток заранее.

## Атрибуция: кому засчитать покупку

Перед покупкой человек может прийти несколько раз из разных каналов: сначала из соцсетей, потом из письма, потом из поиска. **Модель атрибуции** решает, какому каналу засчитать заказ:

| Модель | Как распределяет ценность |
|---|---|
| **последний клик** | всё — последнему каналу перед покупкой |
| **первый клик** | всё — каналу, который привёл впервые |
| **линейная** | поровну всем касаниям |
| **с учётом позиции** | 40% первому, 40% последнему, 20% поровну остальным |
| **data-driven** | по модели, оценивающей вклад каждого канала по данным |

Последний клик переоценивает каналы, которые «дожимают» (поиск по названию бренда, письма), и недооценивает те, что знакомят с продуктом (медийная реклама, соцсети). Но любая модель атрибуции остаётся договорённостью. Честнее всего вклад канала измеряют экспериментами: временно отключают рекламу в части регионов и сравнивают с остальными.

## Приватность

Поведенческие данные — персональные. Закон (в России — 152-ФЗ «О персональных данных») требует согласия пользователя на обработку, а браузеры всё сильнее ограничивают сторонние cookies. Аналитик работает с обезличенными идентификаторами, не выгружает личные данные в открытые места и собирает только то, что нужно для задачи.

## Шпаргалка

| Понятие | Суть |
|---|---|
| событие | кто, что, когда, где, с какими параметрами |
| план трекинга | список событий и параметров до начала сбора |
| сессия | новая, если разрыв больше 30 минут |
| отказ | сессия из одной страницы или очень короткая |
| UTM | `utm_source`, `utm_medium`, `utm_campaign` в ссылке |
| последний клик | вся ценность последнему каналу |
| линейная атрибуция | поровну всем касаниям |
| честный вклад канала | эксперимент с отключением |
