## Дерево метрик

Метрики продукта не живут сами по себе: они связаны. **Дерево метрик** показывает, как главная метрика складывается из более простых, а те — из ещё более простых, вплоть до показателей, на которые команды влияют напрямую.

```text
Выручка
├── Покупатели
│   ├── Новые = посетители × конверсия в первую покупку
│   └── Вернувшиеся = база клиентов × доля вернувшихся
├── Заказов на покупателя (частота)
└── Средний чек
    ├── Товаров в заказе
    └── Средняя цена товара
```

Зачем оно нужно:

- **диагностика**: когда главная метрика изменилась, спускаемся по дереву и находим ветку, где произошло изменение;
- **распределение ответственности**: у каждой ветки — своя команда (маркетинг отвечает за новых, CRM — за вернувшихся, категорийные менеджеры — за средний чек);
- **выбор метрик для экспериментов**: тест меняет нижнюю метрику, а дерево подсказывает, как это отразится на верхней.

## Два способа раскладывать

**Мультипликативно** — метрика равна **произведению** множителей:

```text
выручка = покупатели × заказов на покупателя × средний чек
```

**Аддитивно** — метрика равна **сумме** частей (по сегментам):

```text
выручка = выручка Москвы + выручка Петербурга + … + выручка остальных
выручка = выручка новых клиентов + выручка вернувшихся
```

Хорошее дерево сочетает оба способа: множители показывают **что** изменилось, разрезы — **где**.

## Факторный анализ: сколько дал каждый множитель

Выручка выросла с 10 до 12 млн ₽. Заказов стало больше, но и чек вырос. Сколько из прироста в 2 млн дал каждый фактор? Простой способ — **цепные подстановки**: меняем множители по одному.

```text
выручка = заказы × чек
вклад заказов = (заказы₁ − заказы₀) × чек₀
вклад чека    = заказы₁ × (чек₁ − чек₀)
сумма вкладов = выручка₁ − выручка₀
```

```sql
-- Вклад числа заказов и среднего чека в изменение выручки: апрель → май 2026
WITH m AS (
    SELECT CAST(date_trunc('month', order_date) AS DATE) AS month,
           COUNT(*) AS orders,
           SUM(amount) / COUNT(*) AS avg_check
    FROM orders
    WHERE status = 'delivered'
      AND order_date >= '2026-04-01' AND order_date < '2026-06-01'
    GROUP BY month
),
p AS (
    SELECT MAX(orders)    FILTER (WHERE month = '2026-04-01') AS o0,
           MAX(orders)    FILTER (WHERE month = '2026-05-01') AS o1,
           MAX(avg_check) FILTER (WHERE month = '2026-04-01') AS c0,
           MAX(avg_check) FILTER (WHERE month = '2026-05-01') AS c1
    FROM m
)
SELECT ROUND(o1 * c1 - o0 * c0)  AS revenue_change,
       ROUND((o1 - o0) * c0)     AS from_orders,
       ROUND(o1 * (c1 - c0))     AS from_check
FROM p;
```

Результат зависит от порядка подстановки: сначала заменили заказы или сначала чек. Поэтому его называют приближённым. Есть и симметричные методы (например, логарифмический), но для управленческого вывода «больше заказов, но меньше чек» цепных подстановок хватает.

## Эффект структуры

Средний чек может измениться, даже если **ни одна** категория не подорожала, — просто потому, что изменилась **структура**: люди стали чаще покупать дешёвые товары. Это **эффект структуры** (mix effect).

Пример. Электроника стоит в среднем 30 000 ₽, книги — 800 ₽. Если в этом месяце продали больше книг, средний чек магазина упадёт, хотя цены не менялись. Поэтому при анализе среднего чека всегда смотри **разрез по категориям**: изменилась цена внутри категорий или доля категорий.

```sql
-- Доля категорий в числе проданных товаров и их средняя цена: апрель и май 2026
WITH t AS (
    SELECT CAST(date_trunc('month', o.order_date) AS DATE) AS month,
           p.category,
           SUM(oi.quantity)            AS items,
           SUM(oi.quantity * oi.price) AS revenue
    FROM order_items oi
    JOIN orders o   ON o.order_id = oi.order_id
    JOIN products p ON p.product_id = oi.product_id
    WHERE o.status = 'delivered' AND o.order_date >= '2026-04-01' AND o.order_date < '2026-06-01'
    GROUP BY month, p.category
)
SELECT month, category, items,
       ROUND(100.0 * items / SUM(items) OVER (PARTITION BY month), 1) AS share_pct,
       ROUND(revenue / items) AS avg_price
FROM t
ORDER BY category, month;
```

## Как пользоваться деревом при разборе

1. Сравни главную метрику с прошлым периодом **и** с тем же периодом прошлого года.
2. Разложи на множители. Найди тот, который изменился сильнее всего.
3. Спустись по его ветке: разрезы по сегментам, категориям, платформам.
4. На нижнем уровне ищи **событие**: релиз, акция, сбой, изменение цен, отключённая реклама.
5. Сформулируй вывод сверху вниз: «Выручка −8%: заказов −10% из-за −25% новых клиентов из рекламы; с 12-го числа отключена кампания в поиске».

## Шпаргалка

| Приём | Суть |
|---|---|
| дерево метрик | главная метрика → множители → разрезы → действия команд |
| мультипликативно | `выручка = покупатели × частота × чек` — что изменилось |
| аддитивно | `выручка = Σ по сегментам` — где изменилось |
| цепные подстановки | `вклад_A = ΔA × B₀`, `вклад_B = A₁ × ΔB` |
| эффект структуры | средний показатель меняется из-за долей сегментов |
| разбор | сверху вниз до события, вывод — тоже сверху вниз |
