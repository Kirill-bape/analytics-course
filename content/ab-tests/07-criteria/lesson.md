## Критерий зависит от метрики

В теме про статистические тесты мы разобрали t-тест, Манна — Уитни и хи-квадрат. В A/B-тестах те же инструменты, но со своими особенностями: огромные выборки, метрики с тяжёлым хвостом и соблазн смотреть много срезов сразу.

| Метрика | Чем сравнивать | Что даёт |
|---|---|---|
| конверсия (доля) | z-тест для долей или хи-квадрат | разница долей и p-value |
| среднее (ARPU, чек на пользователя) | t-тест Уэлча | разница средних и p-value |
| среднее с очень тяжёлым хвостом | t-тест + бутстрап для интервала | честный доверительный интервал |
| медиана, квантили | бутстрап | интервал для разницы медиан |
| ratio-метрика (средний чек на заказ) | дельта-метод или бутстрап по пользователям | учёт зависимости заказов одного человека |

## t-тест для выручки: работает, но осторожно

Выручка на пользователя (ARPU) — смесь множества нулей и редких больших покупок. Но благодаря **центральной предельной теореме** на тысячах пользователей **среднее** распределено почти нормально, и t-тест работает. Проблемы начинаются, когда в данных есть экстремальные выбросы: один заказ на миллион может решить исход теста. Тогда помогают бутстрап и снижение дисперсии.

```python
from scipy import stats

ck = ab_users[ab_users["experiment"] == "checkout_v2"]
a = ck[ck["group_name"] == "A"]["revenue"]
b = ck[ck["group_name"] == "B"]["revenue"]

print("ARPU A:", round(a.mean(), 1), " B:", round(b.mean(), 1))
print("p-value:", round(stats.ttest_ind(a, b, equal_var=False).pvalue, 4))
```

## Манн — Уитни отвечает на другой вопрос

Популярная ошибка — проверить выручку тестом Манна — Уитни и написать в отчёте «средний чек вырос». Манн — Уитни сравнивает **ранги**, то есть проверяет, что значения одной группы систематически больше. Он может показать значимость, когда средние не отличаются, и наоборот. Если бизнесу важна выручка — среднее, — сравнивай средние.

## Бутстрап: доверительный интервал для разницы

**Бутстрап** — универсальный способ получить доверительный интервал для любой статистики: разницы средних, медиан, отношений. Многократно берём случайные выборки **с возвращением** из каждой группы, считаем разницу и смотрим на её распределение:

```python
import numpy as np

ck = ab_users[ab_users["experiment"] == "checkout_v2"]
a_arr = ck.loc[ck["group_name"] == "A", "revenue"].to_numpy()
b_arr = ck.loc[ck["group_name"] == "B", "revenue"].to_numpy()

rng = np.random.default_rng(3)
diffs = []
for _ in range(1000):
    sa = rng.choice(a_arr, size=len(a_arr), replace=True)
    sb = rng.choice(b_arr, size=len(b_arr), replace=True)
    diffs.append(sb.mean() - sa.mean())

low, high = np.percentile(diffs, [2.5, 97.5])
print("разница ARPU:", round(b_arr.mean() - a_arr.mean(), 1), " 95% ДИ:", round(low, 1), "…", round(high, 1))
```

Если интервал **не содержит ноль**, разница значима на уровне 5%. Интервал полезнее p-value: он сразу показывает и направление, и **размер** эффекта — «ARPU вырос где-то на 7–88 ₽, скорее всего около 47 ₽».

## Множественные сравнения

После основного результата всегда хочется посмотреть срезы: мобильные и компьютеры, новички и старожилы, Москва и регионы. Каждый срез — ещё один тест, и шанс случайной «находки» растёт:

```text
P(хотя бы одна ложная находка из k тестов) = 1 − (1 − α)^k
```

При 10 срезах и α = 5% это уже около 40%.

Поправки:

- **Бонферрони**: делим α на число тестов k. Просто, но строго: теряем мощность.
- **Холм** — улучшенный Бонферрони: сортируем p-value по возрастанию и сравниваем i-е с α / (k − i + 1). Всегда не хуже Бонферрони.
- **Бенджамини — Хохберг** контролирует не вероятность хотя бы одной ошибки, а **долю ложных открытий** среди найденного (FDR). Мягче, подходит, когда тестов много и важно найти кандидатов для дальнейшей проверки.

```python
from scipy import stats

ck = ab_users[ab_users["experiment"] == "checkout_v2"]
pvals = {}
for device, part in ck.groupby("device"):
    a = part[part["group_name"] == "A"]["converted"]
    b = part[part["group_name"] == "B"]["converted"]
    pvals[device] = stats.ttest_ind(a, b, equal_var=False).pvalue

k = len(pvals)
for device, p in sorted(pvals.items(), key=lambda x: x[1]):
    print(device, round(p, 4), "значимо с Бонферрони" if p < 0.05 / k else "")
```

> ⚠️ Срезы — для понимания, а не для решения. Если общий результат не значим, «значимый эффект на планшетах в Казани» почти наверняка случайность. Такую находку проверяют **новым** тестом.

## Шпаргалка

| Задача | Как |
|---|---|
| конверсия | z-тест / хи-квадрат / t-тест на нулях и единицах |
| ARPU | `stats.ttest_ind(a, b, equal_var=False)` |
| интервал для любой статистики | бутстрап, перцентили 2,5% и 97,5% |
| значимо по бутстрапу | интервал не содержит 0 |
| шанс ложной находки при k тестах | `1 − (1 − α)^k` |
| Бонферрони | порог `α / k` |
| Холм | i-й по возрастанию p сравнить с `α / (k − i + 1)` |
| Бенджамини — Хохберг | контроль доли ложных открытий (FDR) |
