## Зачем ускорять тесты

Размер выборки пропорционален **дисперсии** метрики. Если уменьшить дисперсию вдвое, тот же эффект можно заметить на вдвое меньшей выборке, то есть за вдвое меньшее время. Для компаний, которые запускают сотни тестов, это прямые деньги. Есть три популярных способа:

1. **обработка выбросов** — убрать влияние редких гигантских значений;
2. **стратификация** — учесть, что разные сегменты ведут себя по-разному;
3. **CUPED** — использовать данные о пользователе **до** эксперимента.

А **последовательное тестирование** решает другую задачу: позволяет честно смотреть на результаты по ходу теста и останавливать его раньше.

## Выбросы: обрезка и винзоризация

Один покупатель на 200 000 ₽ в группе из тысяч людей сдвигает ARPU сильнее, чем само изменение. Обычный приём — **винзоризация**: значения выше 99-го процентиля заменяют самим этим процентилем.

```python
import numpy as np

ck = ab_users[ab_users["experiment"] == "checkout_v2"]
cap = ck["revenue"].quantile(0.99)          # порог по обеим группам вместе
capped = ck["revenue"].clip(upper=cap)
print("порог:", round(cap), " дисперсия до:", round(ck["revenue"].var()), " после:", round(capped.var()))
```

Правила:

- порог считают **по обеим группам вместе** и заранее, а не отдельно в каждой группе;
- винзоризация меняет метрику: теперь это «выручка с ограничением сверху». Если изменение как раз нацелено на крупных клиентов, их не режут;
- решение о выбросах фиксируют **до** просмотра результатов, иначе это подгонка.

## Стратификация

Если метрика сильно различается между сегментами (на компьютерах конверсия выше, чем на телефонах), часть дисперсии объясняется **составом группы**. Стратификация убирает эту часть: эффект считают **внутри** каждого сегмента (страты), а затем усредняют с весами страт.

```python
ck = ab_users[ab_users["experiment"] == "checkout_v2"]
by = ck.groupby(["device", "group_name"])["converted"].mean().unstack()
weights = ck["device"].value_counts(normalize=True)
effect = ((by["B"] - by["A"]) * weights).sum()
print(by.round(4))
print("стратифицированный эффект:", round(effect, 4))
```

Выигрыш тем больше, чем сильнее страты отличаются по метрике. Страты должны определяться **до** эксперимента и не зависеть от него: устройство, регион, новизна пользователя.

## CUPED

**CUPED** (Controlled-experiment Using Pre-Experiment Data) использует то, что поведение пользователя до теста предсказывает его поведение в тесте. Кто много тратил раньше, скорее всего, много тратит и сейчас. Эту предсказуемую часть вычитают:

```text
θ = cov(Y, X) / var(X)
Y_cuped = Y − θ × (X − среднее(X))
```

- Y — метрика в тесте (выручка за две недели теста);
- X — та же метрика **до** теста (выручка за две недели до него);
- θ считают по обеим группам вместе.

Среднее `Y_cuped` в каждой группе почти не меняется, а дисперсия падает в (1 − ρ²) раз, где ρ — корреляция X и Y. При ρ = 0,7 дисперсия падает вдвое: тест можно вести вдвое меньше.

```python
import numpy as np

rng = np.random.default_rng(5)
n = 5000
x = rng.gamma(2, 200, size=2 * n)                  # выручка до теста
group = np.repeat(["A", "B"], n)
effect = np.where(group == "B", 15, 0)              # настоящий эффект +15 ₽
y = 0.8 * x + rng.normal(0, 150, size=2 * n) + effect

theta = np.cov(y, x)[0, 1] / np.var(x, ddof=1)
y_cuped = y - theta * (x - x.mean())
print("корреляция:", round(np.corrcoef(x, y)[0, 1], 2))
print("дисперсия Y:", round(y.var()), " после CUPED:", round(y_cuped.var()))
```

Важно: X должен быть измерен **до** начала теста. Иначе изменение может повлиять и на X, и CUPED «съест» часть эффекта.

## Подглядывание и последовательные тесты

В классическом тесте размер выборки фиксируют заранее и смотрят на результат **один раз**. Если проверять p-value каждый день и остановиться при первом p < 0,05, вероятность ложной находки вырастет с 5% до 20–30%: p-value случайно колеблется и рано или поздно ныряет под порог.

Но смотреть по ходу хочется: если новая версия явно ломает покупки, ждать месяц нельзя. Для этого есть **последовательные методы**:

- **SPRT** (тест Вальда) — после каждой порции данных считает отношение правдоподобий гипотез и сравнивает с двумя порогами: пересёк верхний — эффект есть, нижний — эффекта нет, между ними — продолжаем;
- **групповой последовательный дизайн** — заранее назначают несколько промежуточных проверок с более строгими порогами (поправки Покока, О'Брайена — Флеминга);
- **mSPRT** и «всегда валидные» p-value — используются в современных платформах экспериментов.

Правило для практики: если смотришь на тест по ходу, используй метод, который это разрешает. А **защитные метрики** (сломались ли покупки) мониторь ежедневно с самого начала — это не подглядывание, а безопасность.

## Шпаргалка

| Метод | Что делает | Главное правило |
|---|---|---|
| винзоризация | значения выше 99-го процентиля заменяет порогом | порог общий для групп и заранее |
| стратификация | эффект внутри сегментов, затем взвешивание | страты определены до теста |
| CUPED | вычитает предсказуемую по прошлому часть метрики | X — только до начала теста |
| дисперсия после CUPED | `× (1 − ρ²)` | чем выше корреляция, тем больше выигрыш |
| последовательный тест | разрешает честные промежуточные проверки | без него не останавливай тест «по прокрасу» |
