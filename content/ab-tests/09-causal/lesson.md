## Когда A/B-тест невозможен

A/B-тест — золотой стандарт: случайное разбиение гарантирует, что группы отличаются только изменением. Но часто провести его нельзя:

- изменение действует на всех сразу: новые цены, ребрендинг, закон, пандемия;
- **этика**: нельзя оставить часть клиентов без важного исправления;
- **техника**: изменение в мобильном приложении выходит обновлением для всех;
- изменение уже произошло, и нужно оценить его задним числом.

Тогда используют методы **causal inference** — причинного вывода по данным наблюдений. Они пытаются ответить на тот же вопрос: что было бы **без** изменения? Это ненаблюдаемое «как было бы» называют **контрфактическим** сценарием.

## Главный враг — конфаундер

Сравнение «до и после» или «кто воспользовался — кто нет» почти всегда обманывает. Причина — **конфаундеры**: третьи факторы, которые влияют и на воздействие, и на результат.

Пример: те, кто подписался на рассылку, покупают вдвое больше. Значит ли это, что рассылка удваивает покупки? Нет: на рассылку подписываются и так активные клиенты. Активность — конфаундер. Без учёта конфаундеров видимый эффект — смесь настоящего эффекта и разницы между людьми.

## Разность разностей (Difference-in-Differences)

**DiD** — самый популярный и понятный метод. Нужны две группы, обе измерены **до** и **после**:

- **тестовая** — получила изменение (например, город, где запустили бесплатную доставку);
- **контрольная** — не получила (похожий город без изменений).

```text
эффект = (тест_после − тест_до) − (контроль_после − контроль_до)
```

Первая разница — как изменилась тестовая группа. Вторая — как за то же время изменилась контрольная: это естественный тренд и сезонность. Их разность — эффект изменения.

```sql
-- Пример: условная акция в Москве с 1 апреля 2026, контроль — Санкт-Петербург.
-- Средняя дневная выручка до (март) и после (апрель)
WITH d AS (
    SELECT c.city,
           CASE WHEN o.order_date >= '2026-04-01' THEN 'после' ELSE 'до' END AS period,
           SUM(o.amount) / COUNT(DISTINCT o.order_date) AS revenue_per_day
    FROM orders o
    JOIN customers c ON c.customer_id = o.customer_id
    WHERE o.status = 'delivered'
      AND o.order_date >= '2026-03-01' AND o.order_date < '2026-05-01'
      AND c.city IN ('Москва', 'Санкт-Петербург')
    GROUP BY c.city, period
)
SELECT city,
       ROUND(MAX(revenue_per_day) FILTER (WHERE period = 'до'))    AS before,
       ROUND(MAX(revenue_per_day) FILTER (WHERE period = 'после')) AS after
FROM d
GROUP BY city;
```

**Ключевое допущение — параллельные тренды**: без изменения тестовая группа менялась бы так же, как контрольная. Проверить его до конца нельзя, но можно посмотреть на график за несколько месяцев **до** изменения: если линии шли параллельно, допущение правдоподобно. Если тренды и до этого расходились, DiD припишет изменению чужую динамику.

DiD записывают и как регрессию: `y = b0 + b1·тест + b2·после + b3·(тест × после)`. Коэффициент `b3` при произведении и есть эффект, а регрессия заодно даёт стандартную ошибку и p-value.

## Синтетический контроль и Causal Impact

Часто нет одного идеального контрольного города. **Синтетический контроль** собирает «искусственного близнеца» из нескольких: например, 0,5 × Казань + 0,3 × Пермь + 0,2 × Уфа, подобрав веса так, чтобы до изменения близнец повторял тестовый город. После изменения расхождение между городом и его близнецом — оценка эффекта.

**Causal Impact** (библиотека Google) делает похожее с помощью модели временных рядов: по контрольным рядам (ковариатам) прогнозирует, каким был бы тестовый ряд без изменения, и сравнивает с фактом. Требования к ковариатам: сильно связаны с целевым рядом **до** изменения и сами **не затронуты** изменением.

## Матчинг: найти похожих

Если воздействие получили отдельные пользователи (подписались, воспользовались функцией), можно для каждого найти **похожего** пользователя без воздействия: по возрасту, активности, региону, истории покупок. Затем сравнить пары.

**Propensity Score Matching** (PSM) упрощает поиск: сначала логистической регрессией оценивают вероятность получить воздействие по признакам пользователя (propensity score), затем сопоставляют людей с близкими вероятностями. Ограничение всех методов матчинга: они учитывают только **измеренные** признаки. Если активность, мотивация или что-то ещё не записано в данных, эффект останется смешанным.

## Как выбрать метод

| Ситуация | Метод |
|---|---|
| можно случайно разбить | **A/B-тест** — всегда лучший выбор |
| изменение в одном регионе, есть похожий без изменения | разность разностей |
| нет одного хорошего контроля, но много похожих рядов | синтетический контроль, Causal Impact |
| воздействие выбрали сами пользователи | матчинг, PSM, регрессия с контролем признаков |

## Честность выводов

Методы причинного вывода дают оценку **при допущениях**. В отчёте пиши их явно: «эффект +8% при условии, что без акции Москва росла бы так же, как Петербург». Добавляй проверки устойчивости:

- **плацебо-тест**: применить метод к периоду, когда изменения не было. Если и там находится «эффект», методу верить нельзя;
- **другой контроль**: результат не должен сильно меняться от выбора контрольной группы.

## Шпаргалка

| Понятие | Суть |
|---|---|
| контрфактический сценарий | что было бы без изменения |
| конфаундер | фактор, влияющий и на воздействие, и на результат |
| DiD | `(тест_после − тест_до) − (контроль_после − контроль_до)` |
| допущение DiD | параллельные тренды до изменения |
| синтетический контроль | взвешенный «близнец» из нескольких контрольных рядов |
| PSM | пары с близкой вероятностью получить воздействие |
| плацебо-тест | метод не должен находить эффект там, где его не было |
