## Power BI — BI от Microsoft

**Power BI** — одна из самых распространённых BI-систем в крупных компаниях. Он бесплатен для работы на компьютере с Windows (**Power BI Desktop**), а публикация отчётов для коллег идёт через облачный сервис или корпоративный сервер. Работа в Power BI состоит из трёх частей:

1. **Power Query** — загрузка и очистка данных;
2. **модель данных** — таблицы и связи между ними;
3. **DAX** — формулы для мер и столбцов, на которых строятся визуализации.

## Power Query: подготовка данных

Power Query — редактор запросов с кнопками вместо кода. В нём подключаются к источникам (Excel, CSV, базы данных, папки с файлами) и чистят данные: удаляют лишние столбцы, меняют типы, разбивают текст, объединяют таблицы. Каждое действие записывается **шагом**, и при обновлении данных все шаги повторяются автоматически. По сути это та же очистка, что в pandas, только мышкой. Внутри шаги записаны на языке **M**.

> 💡 Правило: всё, что можно сделать в источнике (SQL-запросом к базе), лучше сделать там. Power Query хорош для файлов и небольших преобразований.

## Модель данных: звезда

Хорошая модель Power BI — это **схема «звезда»**:

- в центре **таблица фактов** — события: заказы, продажи, визиты. Много строк, в основном ключи и числа;
- вокруг **таблицы измерений** — справочники: клиенты, товары, календарь. Мало строк, много описаний.

Таблицы связывают **связями** «один ко многим» (1:*): один клиент — много заказов. Фильтр течёт от измерения к фактам: выбрал город в клиентах — отфильтровались его заказы.

Обязательная деталь — отдельная **таблица-календарь** с каждым днём, месяцем, кварталом и годом. Без неё не работают функции сравнения периодов (time intelligence).

## DAX: меры и вычисляемые столбцы

В DAX два вида формул, и путать их — главная ошибка новичков:

| | Вычисляемый столбец | Мера |
|---|---|---|
| когда считается | один раз при загрузке, для каждой строки | каждый раз при показе, в контексте фильтров визуала |
| где хранится | в таблице, занимает память | нигде, это формула |
| пример | `Прибыль строки = Sales[Price] - Sales[Cost]` | `Выручка = SUM(Sales[Amount])` |
| для чего | признак строки: группа, категория | итоги на графиках и в карточках |

Правило: **итоги — мерами**. Средний чек, конверсия, доля — всё это меры:

```text
Выручка        = SUM(Orders[amount])
Заказов        = COUNTROWS(Orders)
Средний чек    = DIVIDE([Выручка], [Заказов])
```

`DIVIDE` — деление, которое не падает с ошибкой при делении на ноль.

## Контекст фильтра и CALCULATE

Одна и та же мера `[Выручка]` в карточке показывает общий итог, а в таблице по городам — выручку каждого города. Это **контекст фильтра**: мера считается для тех строк, которые оставили фильтры визуала, срезы и строки таблицы.

**`CALCULATE`** — главная функция DAX: она меняет контекст фильтра для расчёта.

```text
Выручка доставленных = CALCULATE([Выручка], Orders[status] = "delivered")
Выручка всех городов = CALCULATE([Выручка], ALL(Customers[city]))
Доля города          = DIVIDE([Выручка], [Выручка всех городов])
```

`ALL` снимает фильтр с поля. Поэтому в таблице по городам «Выручка всех городов» в каждой строке одинаковая, и «Доля города» работает как доля от общего итога.

## Сравнение периодов (time intelligence)

С таблицей-календарём DAX умеет сравнивать периоды:

```text
Выручка с начала года  = TOTALYTD([Выручка], 'Календарь'[Дата])
Выручка год назад      = CALCULATE([Выручка], SAMEPERIODLASTYEAR('Календарь'[Дата]))
Рост к прошлому году   = DIVIDE([Выручка] - [Выручка год назад], [Выручка год назад])
```

В SQL то же самое делается оконными функциями и самосоединением по дате минус год — мы это уже умеем:

```sql
-- Выручка с начала года (YTD) по месяцам 2026
WITH m AS (
    SELECT CAST(date_trunc('month', order_date) AS DATE) AS month, SUM(amount) AS revenue
    FROM orders
    WHERE status = 'delivered'
    GROUP BY month
)
SELECT month, revenue,
       SUM(revenue) OVER (PARTITION BY year(month) ORDER BY month) AS revenue_ytd
FROM m
WHERE month >= '2026-01-01'
ORDER BY month;
```

## Отчёт и публикация

Визуализации собирают на страницах отчёта: карточки KPI, графики, таблицы, **срезы** (slicers) — фильтры, которые пользователь щёлкает сам. Взаимодействие между визуалами настраивается: щелчок по столбцу фильтрует остальные. Готовый отчёт публикуют в рабочую область, настраивают расписание обновления данных и права доступа. Можно ограничить строки по ролям (RLS): менеджер видит только свой регион.

## Шпаргалка

| Задача | Как в Power BI |
|---|---|
| загрузить и очистить данные | Power Query, шаги применяются при каждом обновлении |
| связать таблицы | модель «звезда», связи 1:* от измерений к фактам |
| итог на графике | **мера**: `Выручка = SUM(Orders[amount])` |
| признак строки | вычисляемый столбец |
| безопасное деление | `DIVIDE(a, b)` |
| изменить фильтр расчёта | `CALCULATE([мера], условие)` |
| снять фильтр | `ALL(Таблица[поле])` |
| с начала года | `TOTALYTD([мера], 'Календарь'[Дата])` |
| год назад | `CALCULATE([мера], SAMEPERIODLASTYEAR('Календарь'[Дата]))` |
