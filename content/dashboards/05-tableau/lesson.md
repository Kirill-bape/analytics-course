## Tableau — классика визуальной аналитики

**Tableau** — одна из самых известных BI-систем. Её сильная сторона — исследование данных мышкой: перетащил поле, и график перестроился. В России Tableau ушёл с рынка, но его продолжают использовать многие компании, а логика полей, вычислений и уровней детализации встречается во всех BI-системах. Поэтому разобраться в ней полезно, даже если работать придётся в DataLens или Power BI.

Бесплатная версия — **Tableau Public**: работает с файлами, а готовые работы публикуются в открытом профиле. Это удобная витрина для портфолио. Главное — не загружать туда данные, которые нельзя показывать.

## Измерения и меры, синие и зелёные поля

Tableau сам делит поля таблицы на два вида:

| Вид | Что это | Пример |
|---|---|---|
| **измерение** (dimension) | то, по чему группируем | город, категория, дата |
| **мера** (measure) | то, что считаем | сумма, количество |

И ещё на два — по тому, как поле ведёт себя на графике:

- **дискретное** (синяя «пилюля») — отдельные значения, на оси появляются заголовки: «Москва», «Казань», «2026-03»;
- **непрерывное** (зелёная «пилюля») — шкала: на оси появляется числовая ось или непрерывное время.

Одна и та же дата бывает синей (столбец на каждый месяц) и зелёной (сплошная линия времени). Именно цвет «пилюли», а не тип данных, определяет вид графика.

## Полки и карточка Marks

График строят перетаскиванием полей:

- **Columns** и **Rows** — что пойдёт по горизонтали и вертикали;
- **Marks** — как выглядят отметки: цвет, размер, подписи, подсказки, детализация;
- **Filters** — какие данные попадают на лист.

Перетащил `Category` в Rows, `SUM(Sales)` в Columns — получились горизонтальные столбцы. Добавил `Region` в Color — столбцы раскрасились по регионам. За каждым таким действием Tableau сам пишет запрос с `GROUP BY` к данным.

## Вычисления: три уровня

**1. Расчёт на уровне строки** — новое поле для каждой строки данных, как столбец в SQL:

```text
[Прибыль] = [Sales] - [Cost]
[Год заказа] = YEAR([Order Date])
```

**2. Агрегатное вычисление** — формула над итогами. Маржинальность — это не среднее маржинальностей строк, а отношение сумм:

```text
[Маржинальность] = SUM([Profit]) / SUM([Sales])
```

**3. Табличное вычисление** (table calculation) — расчёт по уже построенной таблице результатов: накопительный итог, доля от общего, разница с прошлым периодом, ранг, скользящее среднее. Это аналог оконных функций SQL. Направление расчёта (по строкам, по столбцам, внутри какой группы) задаётся отдельно, и это главный источник ошибок.

```sql
-- Табличные вычисления на SQL: накопительная выручка и доля месяца в году
WITH m AS (
    SELECT CAST(date_trunc('month', order_date) AS DATE) AS month, SUM(amount) AS revenue
    FROM orders
    WHERE status = 'delivered' AND order_date < '2026-01-01'
    GROUP BY month
)
SELECT month, revenue,
       SUM(revenue) OVER (ORDER BY month) AS running_total,
       ROUND(100.0 * revenue / SUM(revenue) OVER (), 1) AS pct_of_year
FROM m
ORDER BY month;
```

## LOD-выражения: свой уровень детализации

Иногда нужно посчитать что-то на **другом уровне**, чем построен график. Например, на графике выручка по месяцам, а нужен месяц **первой покупки** каждого клиента (когорта). Для этого есть **LOD-выражения** (Level of Detail):

```text
{FIXED [Customer ID] : MIN([Order Date])}     — дата первого заказа каждого клиента
{FIXED : SUM([Sales])}                         — общий итог, независимо от графика
{INCLUDE [Customer ID] : SUM([Sales])}         — добавить уровень клиента к текущему
{EXCLUDE [Region] : SUM([Sales])}              — убрать регион из текущего уровня
```

`FIXED` — самое частое. Это ровно то, что в SQL делают подзапросом или CTE с `GROUP BY customer_id`:

```sql
-- {FIXED customer_id : MIN(order_date)} — месяц первого заказа = когорта клиента
WITH first_order AS (
    SELECT customer_id, CAST(date_trunc('month', MIN(order_date)) AS DATE) AS cohort
    FROM orders
    GROUP BY customer_id
)
SELECT cohort, COUNT(*) AS new_clients
FROM first_order
GROUP BY cohort
ORDER BY cohort
LIMIT 6;
```

## Фильтры, параметры и действия

- **Фильтры** работают в определённом порядке: сначала фильтры источника и контекста, потом фильтры измерений, потом мер, потом табличные вычисления. Поэтому `FIXED` не реагирует на обычный фильтр измерения, пока тот не сделан фильтром контекста.
- **Параметр** — переменная, которую пользователь меняет сам: выбрать метрику для графика («Выручка / Заказы / Средний чек») или уровень детализации («день / неделя / месяц»).
- **Действия** (actions) связывают графики на дашборде: кликнул по региону на карте — остальные графики отфильтровались по нему.

## Дашборд в Tableau

Дашборд собирают из готовых листов. Раскладку держат **контейнерами** (горизонтальными и вертикальными блоками), задают фиксированный размер под экран пользователя, добавляют заголовок, фильтры и подписи источника данных. Правила из темы про проектирование дашборда работают и здесь: главное — сверху слева, от общего к частному, у каждой цифры есть сравнение.

## Шпаргалка

| Понятие | Что значит | Аналог в SQL |
|---|---|---|
| измерение / мера | по чему группируем / что считаем | `GROUP BY` / агрегат |
| синяя / зелёная «пилюля» | дискретное / непрерывное | — |
| расчёт на уровне строки | новое поле для каждой строки | выражение в `SELECT` |
| агрегатное вычисление | формула над итогами | `SUM(a) / SUM(b)` |
| табличное вычисление | накопительный итог, доля, ранг | оконные функции `OVER (…)` |
| `{FIXED x : агрегат}` | агрегат на уровне x | CTE с `GROUP BY x` + `JOIN` |
| параметр | переменная от пользователя | параметр запроса |
| действие | клик по графику фильтрует другие | — |
