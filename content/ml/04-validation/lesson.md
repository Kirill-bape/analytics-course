## Проверять на новых данных

Модель создают, чтобы предсказывать **будущее**: клиентов, которых она ещё не видела. Если проверить её на тех же данных, на которых она училась, оценка окажется завышенной. Это как проверять ученика задачами, ответы на которые он заучил.

Поэтому данные делят:

- **обучающая выборка (train)** — на ней подбирают параметры;
- **тестовая выборка (test)** — откладывают и используют только для финальной оценки (обычно 20–30% данных).

```python
cut = pd.Timestamp("2026-04-01")
hist = orders[orders["order_date"] < cut]
df = hist.groupby("customer_id").agg(frequency=("order_id", "count"), last=("order_date", "max"))
df["recency"] = (cut - df["last"]).dt.days
df["returned"] = df.index.isin(orders.loc[orders["order_date"] >= cut, "customer_id"]).astype(int)

rng = np.random.default_rng(42)          # зерно: при каждом запуске одно и то же разбиение
idx = rng.permutation(len(df))           # случайный порядок строк
n_test = int(len(df) * 0.3)
train, test = df.iloc[idx[n_test:]], df.iloc[idx[:n_test]]
print(len(train), len(test))
```

## Переобучение и недообучение

- **Переобучение (overfitting)** — модель запомнила обучающие примеры вместе с их шумом: на train почти идеально, на test плохо. Бывает у слишком сложных моделей: глубоких деревьев, k-NN с k = 1.
- **Недообучение (underfitting)** — модель слишком простая и плохо работает везде.

Признак переобучения — **большой разрыв** между качеством на train и на test.

## Кросс-валидация

Одно разбиение может оказаться удачным или неудачным случайно. **k-fold кросс-валидация** делит данные на k частей (обычно 5). Модель обучают k раз: каждый раз одна часть служит тестом, остальные — обучением. Итоговая оценка — среднее по k запускам, а разброс между ними показывает её надёжность.

> ⚠️ Для данных во времени (продажи, спрос) случайное разбиение — ошибка: модель «увидит будущее». Делят по времени: учатся на прошлом, проверяют на следующем периоде.

## Матрица ошибок

Для классификации все ответы раскладывают в четыре клетки:

| | предсказали «вернётся» | предсказали «не вернётся» |
|---|---|---|
| **вернулся** | TP — верно найден | FN — пропущен |
| **не вернулся** | FP — ложная тревога | TN — верно отсеян |

Из них считают метрики:

| Метрика | Формула | Вопрос |
|---|---|---|
| accuracy | (TP + TN) / все | какая доля ответов верна |
| **precision** (точность) | TP / (TP + FP) | из тех, кого назвали «вернётся», сколько правда вернулись |
| **recall** (полнота) | TP / (TP + FN) | какую долю вернувшихся нашли |
| **F1** | 2·P·R / (P + R) | баланс точности и полноты |

```python
cut = pd.Timestamp("2026-04-01")
hist = orders[orders["order_date"] < cut]
df = hist.groupby("customer_id").agg(last=("order_date", "max"))
df["recency"] = (cut - df["last"]).dt.days
df["returned"] = df.index.isin(orders.loc[orders["order_date"] >= cut, "customer_id"]).astype(int)

pred = (df["recency"] <= 60).astype(int)
print(pd.crosstab(df["returned"], pred, rownames=["факт"], colnames=["прогноз"]))
```

Precision и recall тянут в разные стороны. Если сдвинуть порог так, чтобы «вернётся» говорили чаще, полнота растёт, а точность падает. Выбор зависит от цены ошибок: пропустить мошенника дороже, чем зря проверить честную операцию, — значит, важнее recall.

## ROC AUC

Многие модели выдают не класс, а **оценку** (вероятность). **ROC AUC** показывает, насколько хорошо оценка упорядочивает объекты, без выбора порога: это вероятность того, что случайный объект класса 1 получит оценку выше, чем случайный объект класса 0.

- 0,5 — модель не лучше монетки;
- 0,7–0,8 — неплохо; 0,8–0,9 — хорошо;
- 1,0 — идеально (и подозрительно: проверь утечку).

ROC-кривая строится так: для каждого порога откладывают долю найденных единиц (recall) против доли ложных тревог среди нулей. AUC — площадь под этой кривой.

## Метрики регрессии

MAE, RMSE, MAPE и R² — из прошлого урока. Их тоже считают только на тестовой выборке и сравнивают с baseline («всегда среднее» или «как в прошлом месяце»).

## Шпаргалка

| Понятие | Суть |
|---|---|
| train / test | учимся на одном, проверяем на другом |
| переобучение | train ≫ test |
| k-fold | k обучений, оценка — среднее |
| разбиение по времени | для данных, где важен порядок дат |
| precision | точность срабатываний |
| recall | доля найденных |
| ROC AUC | качество упорядочивания, 0,5 — случайно |
