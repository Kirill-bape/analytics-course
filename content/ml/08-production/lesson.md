## Модель в ноутбуке ещё ничего не приносит

Модель с хорошим ROC AUC в Jupyter — только половина работы. Пользу она начинает приносить, когда её предсказания каждый день попадают туда, где принимают решения: в CRM, рассылку, приложение, отчёт. Этот путь называют **MLOps** — практики вывода моделей в работу и поддержки их там.

## Конвейер: подготовка + модель

Модель обучалась на подготовленных признаках: заполненных пропусках, стандартизации по обучающим средним, one-hot. В работе с новыми данными нужно повторить **ту же** подготовку с **теми же** параметрами. Поэтому подготовку и модель сохраняют вместе — как один **конвейер (pipeline)**.

## Сохранение модели

```py
import joblib
from sklearn.pipeline import make_pipeline

pipe = make_pipeline(prep, LogisticRegression()).fit(X_train, y_train)
joblib.dump(pipe, "churn_model_2026-04.joblib")       # сохранить

pipe = joblib.load("churn_model_2026-04.joblib")       # загрузить в другом процессе
proba = pipe.predict_proba(new_clients)[:, 1]
```

Вместе с моделью записывают: дату и данные обучения, версии библиотек, метрики на тесте, параметры. Для этого есть **MLflow** и подобные реестры моделей. Простую модель (порог, коэффициенты) можно хранить и обычным JSON:

```python
import json

model = {"name": "returned_v1", "trained_on": "2026-04-01", "feature": "recency", "threshold": 70}
text = json.dumps(model, ensure_ascii=False)
print(text)
print(json.loads(text)["threshold"])
```

> ⚠️ Файлы `pickle` и `joblib` при загрузке могут выполнить произвольный код. Загружай только модели из надёжных источников.

## Как модель отдаёт предсказания

| Способ | Как работает | Пример |
|---|---|---|
| **пакетный (batch)** | по расписанию считать прогнозы для всех и записать в таблицу | каждую ночь — вероятность возврата для всех клиентов → в CRM |
| **онлайн (API)** | сервис отвечает на запрос за миллисекунды | проверка платежа на мошенничество в момент оплаты |
| **потоковый** | обработка событий из Kafka | рекомендации по кликам в реальном времени |

Пакетный способ проще всего и закрывает большинство задач аналитики: задача в Airflow загружает модель, считает признаки на сегодня, пишет прогнозы в таблицу хранилища. Онлайн-сервис обычно делают на **FastAPI**:

```py
from fastapi import FastAPI
app = FastAPI()
model = joblib.load("churn_model.joblib")

@app.post("/predict")
def predict(client: dict):
    return {"proba": float(model.predict_proba(pd.DataFrame([client]))[0, 1])}
```

## Модели стареют

Мир меняется: новые каналы привлечения, сезонность, изменения цен. Модель, обученная год назад, постепенно ошибается чаще. Поэтому за моделью следят:

- **качество**: когда приходят настоящие ответы (через 3 месяца стало известно, кто вернулся), считают метрики и сравнивают с тестовыми;
- **дрейф данных**: распределения признаков сравнивают с обучающими, не дожидаясь ответов.

Популярная мера дрейфа — **PSI (population stability index)**:

1. разбить значения признака в обучающем периоде на 10 корзин по децилям;
2. посчитать доли текущих данных в тех же корзинах;
3. `PSI = Σ (текущая доля − обучающая доля) × ln(текущая доля / обучающая доля)`.

| PSI | Вывод |
|---|---|
| < 0,1 | распределение стабильно |
| 0,1–0,25 | заметный сдвиг, присмотреться |
| > 0,25 | сильный дрейф, модель пора проверять и переобучать |

Переобучение часто ставят в расписание (например, раз в месяц на свежих данных), а новую модель перед заменой старой проверяют на отложенных данных или в A/B-тесте.

## Kaggle — тренажёр

**Kaggle** — площадка соревнований по анализу данных. Организатор даёт обучающие данные и закрытый тест; участники присылают прогнозы и видят место в **публичном рейтинге (public leaderboard)**, посчитанном на части теста. Итоговые места определяет **приватный рейтинг** на остальной части.

Чему учит Kaggle:

- признакам, ансамблям, бустингам: в открытых ноутбуках победителей много приёмов;
- честной валидации: кто подгоняет модель под публичный рейтинг, тот падает в приватном (**shake-up**). Доверяй своей кросс-валидации больше, чем публичному рейтингу.

Для портфолио аналитика полезнее одно-два аккуратных соревнования с понятным разбором, чем десятки «сабмитов» без выводов.

## Как объяснить модель бизнесу

- говорить на языке решения: «список из 500 клиентов, из которых 70% вернутся без промокода — им скидку не даём»;
- переводить метрики в деньги: сколько сэкономим или заработаем по сравнению с текущим процессом;
- показывать, какие признаки влияют на прогноз (важность, SHAP), и честно называть ограничения.

## Шпаргалка

| Понятие | Суть |
|---|---|
| pipeline | подготовка признаков + модель как одно целое |
| joblib / pickle / JSON | сохранение модели |
| batch / онлайн | прогнозы по расписанию / по запросу |
| мониторинг | качество по факту + дрейф признаков |
| PSI | мера сдвига распределения: < 0,1 стабильно, > 0,25 дрейф |
| MLflow | реестр моделей и экспериментов |
| public / private leaderboard | не подгоняй модель под публичный рейтинг |
