## Правила, которые находит компьютер

Обычная программа работает по правилам, которые написал человек: «если клиент не покупал 60 дней — отправить промокод». **Машинное обучение (ML)** переворачивает подход: мы даём компьютеру много **примеров с ответами**, и он сам подбирает правило, которое лучше всего их объясняет. Такое найденное правило называется **моделью**.

Аналитику ML нужен для задач вида «предсказать по известному неизвестное»:

- вернётся ли клиент, уйдёт ли в отток;
- какой будет спрос на товар на следующей неделе;
- какой товар предложить покупателю;
- мошенническая ли это транзакция.

## Словарь

| Термин | Что это | Пример |
|---|---|---|
| объект | то, про что делаем предсказание | клиент |
| признаки (features, `X`) | что мы знаем об объекте | сколько дней назад была покупка, сколько заказов |
| целевая переменная (target, `y`) | что хотим предсказать | вернулся ли клиент (1 или 0) |
| обучение | подбор параметров модели по примерам | найти лучший порог по давности покупки |
| предсказание | ответ модели для нового объекта | «вернётся с вероятностью 0,8» |

## Виды задач

- **Обучение с учителем** — есть примеры с правильными ответами:
  - **регрессия**: предсказать **число** (выручку, спрос, время доставки);
  - **классификация**: предсказать **класс** (вернётся / не вернётся, спам / не спам).
- **Обучение без учителя** — ответов нет, ищем структуру: **кластеризация** (сегменты клиентов), **снижение размерности**.
- **Обучение с подкреплением** — агент учится действовать методом проб и ошибок, получая награду.

## Наш учебный набор: вернётся ли клиент

Во всём модуле будем работать с одной задачей. Возьмём «сегодня» = 1 апреля 2026. Для каждого клиента, который уже что-то покупал, посчитаем признаки по истории **до** этой даты, а целевую переменную — **за следующие три месяца**: вернулся ли он и купил ли снова.

```python
cut = pd.Timestamp("2026-04-01")
hist = orders[orders["order_date"] < cut]
df = hist.groupby("customer_id").agg(
    frequency=("order_id", "count"),       # сколько заказов было
    monetary=("amount", "sum"),            # на какую сумму
    last=("order_date", "max"),
    first=("order_date", "min"),
)
df["recency"] = (cut - df["last"]).dt.days    # дней с последней покупки
df["tenure"] = (cut - df["first"]).dt.days    # дней с первой покупки
df["returned"] = df.index.isin(orders.loc[orders["order_date"] >= cut, "customer_id"]).astype(int)

print(len(df), "клиентов, вернулись:", round(df["returned"].mean(), 3))
print(df[["recency", "frequency", "monetary", "tenure", "returned"]].head())
```

> ⚠️ Признаки берутся строго **из прошлого** относительно даты среза, а ответ — **из будущего**. Если в признаки попадёт информация из будущего (например, «число заказов в апреле»), модель покажет блестящую точность на истории и окажется бесполезной в жизни. Это называется **утечкой данных (data leakage)** — самая частая ошибка новичков.

## Самая простая модель — порог

Модель не обязана быть сложной. Правило «вернётся, если последняя покупка была не раньше чем `t` дней назад» — это модель с одним параметром `t`. **Обучить** её — значит перебрать значения `t` и выбрать то, при котором модель чаще всего угадывает:

```python
cut = pd.Timestamp("2026-04-01")
hist = orders[orders["order_date"] < cut]
df = hist.groupby("customer_id").agg(last=("order_date", "max"))
df["recency"] = (cut - df["last"]).dt.days
df["returned"] = df.index.isin(orders.loc[orders["order_date"] >= cut, "customer_id"]).astype(int)

for t in [30, 60, 90, 180]:
    pred = (df["recency"] <= t).astype(int)
    accuracy = (pred == df["returned"]).mean()
    print(f"порог {t:>3} дней: угадали {accuracy:.1%}")
```

**Accuracy (доля правильных ответов)** — самая понятная метрика. Но её всегда сравнивают с **базовой моделью (baseline)**: например, «всегда отвечать самым частым классом». Если сложная модель не обгоняет baseline, она не нужна.

## Как устроен ML-проект

1. **Постановка**: какое решение примут по предсказанию? Как измерим пользу?
2. **Данные**: объект, признаки, целевая переменная, дата среза.
3. **Признаки**: очистка, кодирование, новые признаки.
4. **Разбиение** на обучающую и тестовую выборки.
5. **Обучение** нескольких моделей и сравнение с baseline.
6. **Оценка** на тестовых данных подходящей метрикой.
7. **Внедрение** и мониторинг.

В индустрии модели обучают библиотекой **scikit-learn**, а на табличных данных чаще всего побеждают градиентные бустинги **CatBoost**, **LightGBM**, **XGBoost**:

from sklearn.linear_model import LogisticRegression
