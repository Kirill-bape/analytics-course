## Из многих строк — одно число

До сих пор запросы возвращали строки из таблицы. Но руководителю обычно нужны не тысячи строк, а ответы: «Сколько у нас клиентов?», «Какая выручка за месяц?», «Какой средний чек?».

Для этого есть **агрегатные функции** — они сворачивают много строк в одно число:

| Функция | Что считает | Пример вопроса |
|---|---|---|
| `COUNT(*)` | количество строк | Сколько всего заказов? |
| `COUNT(столбец)` | количество **непустых** значений | У скольких клиентов указана дата рождения? |
| `COUNT(DISTINCT столбец)` | количество **разных** значений | Сколько разных клиентов делали заказы? |
| `SUM(столбец)` | сумма | Какая выручка? |
| `AVG(столбец)` | среднее | Какой средний чек? |
| `MIN(столбец)` / `MAX(столбец)` | минимум / максимум | Самый дешёвый и самый дорогой заказ? |

```sql
SELECT COUNT(*) AS orders_cnt
FROM orders;
```

## COUNT: три варианта

```sql
SELECT COUNT(*)                    AS all_customers,
       COUNT(birth_date)           AS with_birth_date,
       COUNT(DISTINCT city)        AS cities
FROM customers;
```

- `COUNT(*)` считает все строки;
- `COUNT(birth_date)` — только строки, где дата рождения **не пустая** (`NULL` пропускаются);
- `COUNT(DISTINCT city)` — сколько **разных** городов.

## Главные метрики магазина

**Выручка** — сумма всех оплаченных и доставленных заказов. **Средний чек** — средняя сумма заказа. Отменённые и возвращённые заказы обычно не учитывают — поэтому почти всегда нужен `WHERE`:

```sql
SELECT SUM(amount)           AS revenue,
       COUNT(*)              AS orders_cnt,
       ROUND(AVG(amount), 2) AS avg_check,
       MIN(amount)           AS min_order,
       MAX(amount)           AS max_order
FROM orders
WHERE status = 'delivered';
```

Сначала `WHERE` отбирает строки, **потом** агрегатные функции считают итог по оставшимся.

Функции `MIN` и `MAX` работают и с датами:

```sql
SELECT MIN(order_date) AS first_order,
       MAX(order_date) AS last_order
FROM orders;
```

## Агрегаты и NULL

Все функции, кроме `COUNT(*)`, **пропускают** пустые значения. Например, `AVG(rating)` считает средний рейтинг только по товарам, у которых рейтинг есть:

```sql
SELECT COUNT(*)      AS products,
       COUNT(rating) AS with_rating,
       ROUND(AVG(rating), 2) AS avg_rating
FROM products;
```

## Доли и проценты: считаем по условию

Какая доля заказов оформлена с промокодом? Трюк: превратить условие в 1 или 0 через `CASE`, а потом посчитать сумму или среднее:

```sql
SELECT ROUND(
         SUM(CASE WHEN promo_code IS NOT NULL THEN 1 ELSE 0 END) * 100.0 / COUNT(*),
       1) AS promo_share_pct
FROM orders;
```

`SUM(CASE WHEN … THEN 1 ELSE 0 END)` — количество строк, где условие верно. Делим на `COUNT(*)` — получаем долю.

> 💡 В PostgreSQL и DuckDB есть и более короткая запись: `COUNT(*) FILTER (WHERE promo_code IS NOT NULL)`.

## Чего пока нельзя

Нельзя одновременно вывести обычный столбец и итог:

```sql
SELECT city, COUNT(*)
FROM customers;
```

База не понимает, какой из 3 000 городов показать рядом с одним числом. Чтобы посчитать итог **для каждого города**, нужна группировка `GROUP BY` — это первая тема продвинутого модуля.

## Шпаргалка

| Задача | Как написать |
|---|---|
| сколько строк | `COUNT(*)` |
| сколько уникальных | `COUNT(DISTINCT customer_id)` |
| выручка | `SUM(amount)` |
| средний чек | `ROUND(AVG(amount), 2)` |
| доля в % | `SUM(CASE WHEN условие THEN 1 ELSE 0 END) * 100.0 / COUNT(*)` |
