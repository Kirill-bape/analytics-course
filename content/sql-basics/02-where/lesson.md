## Зачем фильтровать

Почти любой вопрос бизнеса начинается с «покажи только…»: только клиентов из Казани, только отменённые заказы, только товары дороже 10 000 ₽. Для этого есть `WHERE` — «где».

```sql
SELECT full_name, city
FROM customers
WHERE city = 'Казань';
```

`WHERE` проверяет **каждую строку** таблицы: если условие верно — строка попадает в результат, если нет — отбрасывается. Как фильтр в Excel, только записанный словами.

## Операторы сравнения

| Оператор | Значение | Пример |
|---|---|---|
| `=` | равно | `status = 'delivered'` |
| `<>` или `!=` | не равно | `status <> 'cancelled'` |
| `>` / `<` | больше / меньше | `price > 50000` |
| `>=` / `<=` | больше или равно / меньше или равно | `amount >= 1000` |

```sql
SELECT product_name, price
FROM products
WHERE price > 50000;
```

## Кавычки: главное правило

- **Текст и даты** пишут в **одинарных** кавычках: `'Казань'`, `'2026-06-01'`.
- **Числа** — без кавычек: `price > 1000`.
- Двойные кавычки `"..."` в SQL означают **название столбца**, а не текст. `city = "Казань"` — ошибка!

И ещё: текст сравнивается **с учётом регистра**. `'Казань'` и `'казань'` — разные значения. Как именно написаны значения, видно в данных и в «Схеме данных».

```sql
SELECT order_id, order_date, amount
FROM orders
WHERE order_date >= '2026-06-25';
```

## Несколько условий: AND и OR

- `AND` — «и»: должны выполняться **оба** условия;
- `OR` — «или»: достаточно **одного** из условий.

```sql
-- Дорогие товары из категории «Электроника»
SELECT product_name, category, price
FROM products
WHERE category = 'Электроника' AND price > 40000;
```

> ⚠️ **Ловушка со скобками.** `AND` выполняется раньше `OR` — как умножение раньше сложения в математике. Поэтому когда в условии есть и `AND`, и `OR`, **всегда ставь скобки**.

Нужно: заказы, оплаченные наличными, которые отменили **или** вернули.

```sql
-- ✅ Правильно: скобки объединяют «отменили или вернули»
SELECT order_id, status, payment_method
FROM orders
WHERE payment_method = 'cash'
  AND (status = 'cancelled' OR status = 'returned');
```

Без скобок база прочитает условие как «(наличные И отменён) ИЛИ возвращён» — и в результат попадут все возвраты, даже оплаченные картой. Попробуй убрать скобки в примере выше и посмотри на столбец `payment_method`.

## Список значений: IN

Вместо длинной цепочки `OR` удобно написать список:

```sql
SELECT full_name, city
FROM customers
WHERE city IN ('Казань', 'Самара', 'Уфа');
```

`NOT IN (...)` — наоборот, всё, кроме перечисленного.

## Диапазон: BETWEEN

`BETWEEN a AND b` — значение от `a` до `b` **включительно** (обе границы входят):

```sql
SELECT product_name, price
FROM products
WHERE price BETWEEN 1000 AND 2000;
```

Это то же самое, что `price >= 1000 AND price <= 2000`.

## Поиск по части текста: LIKE

`LIKE` ищет по шаблону:

- `%` — любое количество любых символов (в том числе ноль);
- `_` — ровно один любой символ.

```sql
-- Названия, которые начинаются со слова «Смартфон»
SELECT product_name, price
FROM products
WHERE product_name LIKE 'Смартфон%';
```

`'%Xiaomi%'` — слово Xiaomi в любом месте названия. `LIKE` различает большие и маленькие буквы. Если регистр не важен, используй `ILIKE` (работает в PostgreSQL и DuckDB):

```sql
SELECT product_name
FROM products
WHERE product_name ILIKE '%xiaomi%';
```

## NOT — отрицание

`NOT` переворачивает условие: `NOT city = 'Москва'`, `NOT IN (...)`, `NOT LIKE '...'`.

## Порядок частей запроса

```text
SELECT  столбцы
FROM    таблица
WHERE   условие
LIMIT   число
```

`WHERE` всегда идёт после `FROM` и перед `LIMIT`.

## Шпаргалка

| Задача | Как написать |
|---|---|
| точное совпадение | `city = 'Москва'` |
| несколько вариантов | `city IN ('Москва', 'Тула')` |
| диапазон | `price BETWEEN 100 AND 500` |
| содержит текст | `product_name ILIKE '%набор%'` |
| сложное условие | `a = 1 AND (b = 2 OR b = 3)` |
